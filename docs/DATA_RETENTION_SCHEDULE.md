# Heavyar data retention schedule

All durations below are **OWNER OPERATIONAL POLICY**, not statements of a statutory Saudi duration. An active legal, accounting, security, payment, complaint, incident, or litigation hold suspends destruction. Backups expire through provider lifecycle controls; records are not selectively restored except for disaster recovery and are deleted/anonymized again when restored.

| Category | Purpose / system / owner | Active-account rule | Post-deletion and holds | Destruction/anonymization and enforcement |
|---|---|---|---|---|
| Firebase identity and user/profile | authentication and marketplace identity / Firebase / Security | account lifetime | identity revoked; profile deleted/minimized; protected owner/staff accounts require governed process | deletion job, refresh-token revocation, Auth deletion, profile field minimization |
| Equipment/listings and Cloudinary media | marketplace inventory / Firestore + Cloudinary / Operations | listing lifetime plus 24 months archived | delete owned drafts/media; anonymize shared historical snapshot references; preserve active dispute evidence | deletion state machine and scoped Cloudinary owner namespace cleanup |
| Rental/request and chat/messages | contract performance and evidence / Firestore / Operations | account lifetime and transaction lifecycle | retain immutable financial/commercial snapshots and dispute evidence for 7 years from transaction closure; anonymize participant-facing profile data when eligible | protected deletion collection rules; deletion job anonymization |
| Ratings | marketplace trust / Firestore / Trust | while relevant to marketplace integrity | retain de-identified transaction-linked rating for 24 months unless held | UID/name minimization and scheduled review |
| Complaints, disputes and incidents | case resolution/safety evidence / Firestore / Support | case lifecycle | 7 years after closure when connected to transaction/payment; otherwise 3 years | case states, hold marker, later anonymization job |
| Payment metadata and invoices | settlement/accounting / Firestore + Tap references / Finance | transaction lifecycle | 7 years from transaction date under owner accounting policy or longer active hold; no raw card/CVV | retained by deletion state machine; immutable snapshots; controlled finance access |
| Notification inbox | user communication / Firestore / Product | 180 days | delete on account deletion unless protected case evidence | every created inbox record receives `expiresAt`; scheduled allowlisted deletion |
| Delivery artifacts/outbox | delivery retry and diagnostics / Firestore / Operations | delivery records 30 days; outbox follows the source notification’s 180-day maximum | delete | explicit `expiresAt`, bounded scheduled cleanup, and manual audited cleanup fallback |
| Device/push tokens and ownership indexes | push routing / Firestore/Expo-FCM / Product | active registrations renew a 180-day expiry; revoked/permanently invalid records expire after 30 days | delete and release ownership | device revoke, deletion job, and scheduled `expiresAt` cleanup across token/owner/installation records |
| Policy acceptance | electronic acceptance evidence / Firestore / Compliance | append-only | 7 years after last relevant transaction/account closure or active hold | Worker-only writes; no overwrite; Admin read/RBAC |
| Privacy/deletion requests | PDPL operations / Firestore / Compliance | case lifecycle | 3 years after completion; deletion fulfillment audit remains minimized | state machine and eventual scheduled anonymization |
| Admin/security audit | accountability/security / Firestore / Security | 7 years under owner operational policy | retain minimized actor/action evidence; no secrets | immutable event documents and RBAC |
| Verification status | trust state / Firestore / Trust | capability lifetime | current iOS collects no government ID; expire status/evidence by configured retention | existing verification cleanup; capability disabled where absent |
| Temporary OTP/recovery/rate-limit/cache/upload reservation | abuse prevention/transient operation / KV + Firestore / Security | explicit TTL only, normally minutes to days | delete | provider TTL plus scheduled `expiresAt` cleanup for allowlisted temporary collections, including phone/email/auth recovery guards |

The cleanup processor deletes only records that carry an explicit expired `expiresAt` in an allowlisted temporary collection. It never scans or deletes payments, invoices, rental snapshots, complaints, incidents, refunds, policy acceptances, or audit history.
