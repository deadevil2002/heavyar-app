PHASE 2 GOAL
==================================================

Build the production Admin Dashboard and operational control layer for Heavyar.

The dashboard must use the SAME authoritative backend and state machines as the mobile app.

Do NOT duplicate financial or request business logic in the browser.

Do NOT weaken Phase 0 or Phase 1 security.

Do NOT implement Nafath yet.

Do NOT activate live Tap credentials.

Do NOT redesign the entire customer/provider mobile UI.

Do NOT create another Cloudflare Worker unless there is an unavoidable technical reason. Prefer extending the existing heavyar-api backend.

==================================================
1. ADMIN AUTHORIZATION
==================================================

Implement trusted server-side admin authorization.

Do NOT rely only on:
- hidden routes
- email checks in the browser
- a Firestore role field controlled by the client

Use a trusted server-side mechanism such as Firebase custom claims or an equivalent backend-controlled admin entitlement.

Support at minimum:

super_admin
admin

Architecture should allow future scoped roles such as:
finance_admin
support_admin
operations_admin

Only super_admin may grant or revoke admin privileges.

All privileged admin actions must be checked server-side.

3. DASHBOARD OVERVIEW
==================================================

Create a useful operational dashboard showing trusted backend metrics such as:

- total users

- requests by status

Use suitable indexed queries or trusted aggregates where needed.

- suspend
- unsuspend
- add admin note
- review account history

9. REFUND FOUNDATION
==================================================

Implement safe refund workflow foundations.

Do NOT enable dangerous arbitrary refund actions without provider support and trusted validation.

Architecture should support:

refund_failed

Otherwise:

- clearly mark it as unavailable until provider support is configured

Refunds must be:
- server-authorized
- idempotent
- audited
- tied to original payment
- constrained by original paid amount
